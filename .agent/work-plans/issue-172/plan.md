# Plan: Per-pulse-mode backscatter normalisation (Part B, empirical range residual)

## Issue

https://github.com/rolker/cube_bathymetry/issues/172 (scope narrowed by the operator decisions in its second comment: Part B only; the range term is an empirical per-mode residual, the declared gain state is a recorded check). Part A (declared-TVG residual TL) and the marine_tools research into the M3's gain law are separate follow-ups.

**Acceptance for the narrowed scope.** (1) A per-mode table derived from SonarInfo-bearing bags removes the step between pulse modes in the backscatter mosaic: on Appledore, |median pass-to-pass step| < 2 dB on every bag pair with at least 1000 shared cells, against a baseline measured first with the single curve. (2) Within each mode the corrected level shows no residual trend with range beyond the misfit threshold (the within-mode level-vs-range table is re-run on the corrected data). (3) The table written by the Python derivation is the file the C++ estimator loads (shared fixture round trip). (2) is met by the empirical residual, not by knowing the sonar's gain law.

## Context

Backscatter is corrected at record time (`Hypothesis::recordBeam` -> `correctBeamIntensity`) from one sheet-level `Parameters` curve (`angular_response_curve`, `backscatter_tl_removed`, `backscatter_absorption_db_per_m`), latched first-wins from SonarInfo (node `sonarInfoCallback`) or read once in an `import_bag` pre-pass (`loadCurveFromBagSonarInfo`). The curve is `db_relative_to_nadir`, binned by `|angle|`, so it cannot remove the 10-17 dB offsets between the M3's five pulse modes, and the cube#87 tier-2 add-back (`40 log10 R + 2 alpha R`) double-counts a range gain the sonar already applied. `appledore_backscatter/mode_vs_range.txt` shows within-mode level vs range that one log-range slope cannot fit (20 us CW rises then falls; 50 us CW steps 13 dB; 1 ms FM falls faster with range the way 2 alpha R would).

**Step 0 (done):** `feature/issue-170` was merged into `feature/issue-172` (merge `2afec3e`) because this work builds on its `derive_angular_response.py` (`--box`, TF-positioned pings, seawater absorption, provenance header, tests); PR #171 merged on 2026-10-30 and `origin/jazzy` was merged back in at `14defbe`, so the branch diff against jazzy is #172 work only.

## Design decisions

These are the settled choices; the ADR-0007 D3 amendment in PR 2 draws its text from this section.

1. **Mode key (shared spec).** `<TYPE>_<pulse_us>us_<bw_Hz>Hz` per transmit sector in sector order, sectors joined with `+`, then `_<freq_kHz>kHz` once from the ping's own `PingInfo.frequency`; e.g. `FMU_1000us_24000Hz_500kHz`. TYPE from `tx_signal_types` (1 CW, 2 FMU, 3 FMD, anything else or a missing element UNK; an empty array means UNK for every sector, never CW). Numbers are rounded to 3 significant figures (C `%.2e`, then written as a plain decimal without exponent or trailing zeros), so sub-us pulses on other sonars do not collapse. A NaN, infinite or non-positive raw value (tested BEFORE rounding) or a missing element is `?`. A SonarInfo with no sectors gives one `UNK_?us_?Hz` sector. The key always starts with a letter, so the existing loaders' numeric parse rejects every table row (must-fix 1). Frequency is in the key because it switches per ping on multi-frequency sonars (EM2040, R2Sonic) (must-fix 6). One documented function in the derive script is the spec; `test/data/mode_keys.json` holds raw values -> keys and PR 2's C++ must pass the same vectors. Pings before the first SonarInfo get no key, are counted and are left out. `SonarDetections` has no beam-to-sector map, so a multi-sector ping gets one key for the whole ping (documented limit; the M3 is single-sector). Unkeyed gain state (Kongsberg transmit power re max, receiver fixed gain) is a known limit of the key.
2. **Range model: binned log-range residual per mode AND angle group** (operator decision, replaces the scalar slope; must-fix 4; angle groups added 2026-11-02 after the first Appledore run). Per mode `L(theta, R) = A(theta) + r_g(log10(R/R0))`, `g` the `|theta|` group of the beam (`--range-angle-edges`, default `30,50` → 10-30, 30-50, 50-90 deg; `none` = one group; edges snap up to bin boundaries and the snapped bounds are written). Why groups: run 1 on Appledore left 5-13 dB of range-dependent residual in the 10-30 deg beams of every mode while the pooled residual was 0.6-0.7 dB rms — the M3's residual range dependence is not separable from angle. Every bin belongs to one group and no parameter is shared, so the joint fit separates exactly into one fit per group; a separable sonar gets the same term in every group. **End-node trimming (run 2, 2026-11-02):** an end node of a group's grid carrying under max(200, 0.1 % of the group's beams) is dropped, repeatedly, the weaker end first, counting only the cells inside the current span; beams beyond the kept span are out of the fit and the misfit (counted, corrected with the clamped end value at apply time, and entering the angular intercepts that same way); `r_g` is 0 at R0 when inside the span, else at the nearest end node. Why: on Appledore the 20 µs mode's R0 node held 6e3 of 1e8 beams of junk long-range detections 60 dB off and anchored the whole term (offset +49.5 dB, self-consistent but meaningless `A`). The misfit uses the same share floor per bin. A fit bin whose every beam lies beyond the span is dropped from the fit (its intercept is unused), so a zero count never makes the spread NaN. The angular intercepts `A` are taken over EVERY cell of a bin with the clamped `r_g` (how those beams are corrected at apply time), so specular beams and modes with no range fit keep all their beams. Node spacing is `--range-node-spacing-decades` (default 0.25, the misfit bins at half of it; on Appledore 0.125 did not help). Zero reasons are: under 200 in-span non-specular samples, within-bin spread under 0.03 decade, or a trimmed grid of fewer than two nodes (trimming stops at two). Each `r_g` is defined at nodes every quarter decade of `log10(R/R0)` (node 0 at R0, so `r(R0) = 0`) and is linear between nodes, clamped beyond the end nodes; the estimator applies it the same way, so there are no steps at bin edges. It is fitted per mode jointly with one intercept per SIGNED 2-degree angle bin (fixed effects, so only depth change within an angle bin identifies `r`: on a flat bottom R = h/cos(theta) confounds angle and range across bins), with the specular bins `|theta| < 10` deg left out of the fit. Signed bins keep the cross-track-slope pairing (shorter range with smaller incidence on the up-slope side) out of `r`. A light second-difference penalty keeps thinly supported nodes smooth; each node records its support and standard error. The term is set to zero, with a stated reason, per group, when the group has under 200 non-specular samples or its pooled within-angle-bin spread of `log10 R` is under 0.03 decade (judged within bins, not over the whole span, which is 0.3 decade at 60 deg from angle alone). **Lookup rule** (the contract PR 2's loader implements): a beam uses the range rows whose `angle_lo_deg <= |theta| < angle_hi_deg`; below the first `angle_lo_deg` (specular band) the first group; a mode or group with no range rows has a zero term. The groups are the ones `# range_angle_groups_deg` declares (PR 2 review round 1): the writer omits an unfitted group's rows, so the loader creates every declared group per mode, an unfitted one as a zero term, and the specular band takes the first declared group; only a table without that line uses the groups its rows name.
3. **Angular intercepts referred to R0** (must-fix 3). `A(theta)` per `|theta|` bin (including the specular bins) is the bin mean of `L - r_g(log10(R/R0))` with the bin's own group's term (specular bins: the first group's), so the angle-correlated part of range is not removed twice. The table's `value_db` is `A` (the mode's level at R0); `db_relative_to_nadir` is `A - A(nadir-most bin)`, the curve the estimator subtracts. R0 defaults to the reference mode's median slant range and is recorded (`--range-ref-m` overrides it so campaigns can share one). For a mode whose ranges do not reach R0, each `r_g` is clamped at that group's nearest node, so the between-group anchor differences sit in `A` / `db_relative_to_nadir` and the between-mode difference in the offset (decision 5); the correction stays consistent, but such a mode's angle curve is not a pure angular response (documented).
4. **Misfit diagnostic.** After the fit, the mean residual per eighth-decade bin (half the node spacing, so structure between two nodes shows), pooled, per range-term angle group and per HALF group (split at the integer midpoint bin, only for groups of two or more bins; the per-bin intercepts make a group's pooled residual near zero even when its inner and outer bins still differ in range dependence — the halves are what keeps non-separability visible now that the fit groups and the diagnostic groups coincide), over bins with at least 200 samples AND 0.1 % of the group's fitted beams (bin width = half the node spacing); `misfit_max_db` and `misfit_rms_db` per mode, flagged above `--misfit-threshold-db` (default 1.5 dB). It catches sub-node structure (a step inside a quarter decade) and angle-by-range interaction (non-separability). The diagnostics also fit a scalar log-range slope to the same cells and report its misfit, which shows what a scalar term would miss. If real data exceed the threshold inside a group, narrower groups (`--range-angle-edges`) or finer nodes are the remedy; the format carries node positions and group bounds explicitly, so neither needs a format change.
5. **Absolute offset vs a fixed reference mode.** `--reference-mode`, default `FMU_1000us_24000Hz_500kHz` (the M3 1 ms / 24 kHz FM-up mode), so tables from different campaigns share a reference; when that mode is absent the most-sampled mode is used with a loud "not comparable across campaigns" warning, recorded in the header. At every mode switch, the non-specular (`|theta| >= 10`) beams of the old mode's pings within the adjacency window before the switch and of the new mode's pings within the window after it, each corrected by its own mode's `db_relative_to_nadir` and range term, give one difference (so the offset is the level the new mode reads above the old on their nadir-referred, R0-referred scale, and `raw - db_relative_to_nadir - r_g - offset` puts every mode on the reference mode's nadir level at R0 — the `# offset_meaning:` header line; operator decision 2026-11-02: keep this absolute-to-a-fixed-reference meaning rather than flattening every mode to zero mean, so a sonar with a calibrated level, or a later M3 gain law, has a scale to anchor); a gap wider than the window discards the switch. `--adjacency-window-s` defaults to 2 s (about 40 pings at the M3's rate). Per mode pair the mean difference and its standard error; pairs with fewer than 3 switches are not used. Offsets are chained to the reference by weighted least squares over the pair graph (`o_ref = 0`), with standard errors; a mode with no path to the reference is `offset_anchored=false` with EMPTY offset columns (never 0.000, which a loader would apply; the README's apply rule says such a mode must not be corrected by the table). Details: pair SE floored at 0.01 dB for the weights; up/down agreement needs two switches in each direction; the chain's chi²/dof is reported; `SwitchTracker` discards switches as `gap`, `no_beams` or `out_of_order` and a ping with no key breaks the run; a mode with no usable beams is left out with a warning. **Bias statement** (must-fix 5): removing `r` first stops a range artefact masquerading as an offset, but the switch happens because the depth changed, so the shallower mode always sees the shallower patch, on up- and down-switches alike; where substrate correlates with local depth (rocky highs at Appledore) that bias does not cancel. Errors in `r` also enter times the range distance between the two sides. The diagnostic is the up-switch vs down-switch agreement per pair (difference and combined SE, flagged when it exceeds 1 dB and 3 SE); a residual seabed difference on a sloping bottom shows as disagreement.
6. **Variance and weights.** The derivation measures the sample variance of `L - r_g` per (mode, `|theta|` bin) and writes it with `n` in the table. **PR 2 as built (2026-11-06) does NOT apply `1/variance` as a Welford weight — deviation.** The persisted per-cell statistic is the unweighted Welford `{n, mean, M2}` (eviction spill, and the 3-band `MbesCell` that reconstructs `n` from `sample_sd / standard_error`); a weighted Welford needs the weight sum and the sum of squared weights to stay lossless across eviction, reload and the store round trip, which is a persisted-statistic change this PR does not make. On the M3 the weights are flat, so the product is unchanged; the column's role in PR 2 is the hard cut: a bin with EMPTY `var_db2` is unweighable and a beam in it is uncorrectable (fallback policy). Applying the weights is a filed follow-up (ADR-0007 addendum, Deferred). The original rule, kept for that follow-up: PR 2 uses `1/variance` as the Welford weight, with a hard angle cut only where the variance is not measurable: `var_db2` is written EMPTY for n < 2 and for a variance under 0.0005 dB² (it would print as 0.000), so a loader never divides by zero (review round 2); `se_db` is empty wherever not finite. Carrying it now keeps PR 2 from changing the format. **Operator decision 2026-11-02: keep it** although on the M3 it is nearly flat (105-145 dB², a 10-12 dB per-beam scatter in every bin of every main mode, so the weights change nothing on Appledore) — a sonar whose scatter varies with angle needs it and the format must not change when one turns up. **Rare modes (same decision): keep their entries** however few pings (Appledore: 530 and 169 pings for the 10 ms and 5 ms FM modes against 10⁵-10⁶); `n`, `se_db`, `offset_se_db` are the quality record; a ping whose mode has no entry at all is PR 2's `--backscatter-mode-fallback`, not a derive-time cut.
7. **Table file: `angular-response-table v1`.** One long-format CSV. First line `# format: angular-response-table v1`; tables are detected by that line, never by guessing from rows. Columns `mode,term,x,angle_lo_deg,angle_hi_deg,value_db,n,var_db2,db_relative_to_nadir,se_db,offset_db_vs_ref,offset_se_db,offset_anchored,declared_tvg_model,declared_tvg_absorption_db_per_km`. `term=angle` rows: `x` = `|theta|` bin centre (deg), `value_db` = `A`, `var_db2`, `db_relative_to_nadir`, `se_db`. `term=range` rows: `x` = `log10(R/R0)` node, `angle_lo_deg`/`angle_hi_deg` = the group's snapped bounds, `value_db` = `r_g`, `n` = node support, `se_db`; columns that do not apply are empty. A mode or group with no range rows has a zero range term. The per-mode scalars repeat on every row of the mode (a PR 2 loader rejects rows of a mode that disagree). Header comments record reference mode and its source, R0 and its source, node spacing, the angle groups (`# range_angle_groups_deg:`), the lookup rule (`# range_term_lookup:`), the offset meaning (`# offset_meaning:`), angle bin width, specular exclusion, window, misfit threshold, box, source bags, absorption handling (not modelled separately: the per-mode range term carries it), one `# mode_summary:` line per mode (pings, beams, declared TVG, offset, SE, anchored, misfit max and flag), one `# range_term:` line per mode and group (nodes, span, trimmed nodes, out-of-span count), a `# key_spec:` pointer and an `# empty_fields:` line stating the empty/`nan` cases. `x` is written with 10 significant digits so any bin width or node spacing round-trips. Declared TVG state is a column per mode (and the header summary); a mode seen under more than one declared state is written `MIXED` with a warning. Why one file: one thing to hash for the fingerprint, one `--backscatter-curve` argument, one atomic write. Old binaries: the C++ loader and the marine_tools mirror skip every row (letter-first key) and return an empty curve, which their callers already report loudly as an empty/unparseable curve; both are tested on a table file. A table is never written with `tl_removed`; `--by-mode --remove-tl` is refused (the residual replaces the modelled add-back).
8. **Declared state is a check, not an input** (PR 2). The table records the declared state per mode. The resolver compares each SonarInfo's `tvg_model` / `tvg_absorption_db_per_km` with the table; on mismatch it warns once per (mode, state) pair (node: throttled), counts the pings and still applies the table; the import report prints the per-(mode, state) summary. `UNKNOWN` matches only `UNKNOWN`. No strict flag for now.
9. **Per-ping state** (PR 2). `Parameters` holds a `BackscatterCurveTable`; the legacy curve fields remain only to build the `*` entry. `Sounding` gains `uint16_t correction_idx`: **0 = unresolved, use the table's `*` entry if present, else identity**; a separate reserved value means explicit identity; k >= 1 = entry k-1 (must-fix 2). So the `Sounding(depth)` constructor, existing tests, batch_regen's packed `ScatterRecord` round trip and the live `auto` single-curve path keep applying a legacy curve. Threaded `Sounding` -> `Node::insert` -> `Node::update(..., intensity, beam_angle, range)` -> `Hypothesis::recordBeam` -> `correctBeamIntensity(raw, angle, range, params, idx)`, which picks the range term by the beam's `|angle|` group (decision 2's lookup rule). The resolver (key -> idx, declared-state check, fallback, counters) lives in `backscatter_mode.{h,cpp}`. The depth-adaptive spill record carries `correction_idx`. `--backscatter-mode-fallback identity|exclude` (exclude drops the beam's backscatter, keeps its depth), recorded in the fingerprint. **A table run that resolves nothing (PR 2 review round 1, host direction):** when a table was loaded, pings > 0 and not one resolved to an entry, import_bag prints an `error:` naming the likely causes (wrong `--sonar-info-topic`, no SonarInfo in the bags, no frequency), still writes the store and the fingerprint but with `kind: "table-unresolved"` (ADR-0003; never taken for `table` by `isStale`), and exits 4 (1 and 2 outrank it, it outranks 3; review round 2: the sentence saying what was written is printed after the finish step, once the code is known, so exit 4 and "its fingerprint records table-unresolved" are claimed only when both were written, and a recon-only `--level-plan-out` preflight keeps its own code but says the preflight resolved nothing; review round 3, host direction: the preflight exits 4 too, so exit 4 has one meaning on both paths -- a table was given and no ping resolved a pulse mode; on a full run the store and its `table-unresolved` fingerprint were still written -- and `preflight && import` does not start the import blind); the live node warns at the first unresolved cloud after each configure, throttled to once a minute per configuration while nothing has resolved and, once clouds resolve, once per new reason (review round 2: a rare mode or the ping floor is the normal case, and import_bag treats only "nothing resolved" as an error), with the count and the reason breakdown so far, and keeps the cleanup report. **`nearest` dropped (2026-11-06, deviation):** no metric makes a "nearest mode" honest — modes 10-17 dB apart differ by pulse length only in name, and applying a neighbour's entry would reintroduce the mode steps this issue removes. Added instead: `--backscatter-mode-min-pings <N>` (node `backscatter_mode_min_pings`, default 0 = keep every entry): an entry derived from fewer pings than the floor is treated as absent and the fallback applies — the run-4 answer for the 5 ms FM mode (169 pings, offset swinging −5 to +3 dB), decided at apply time rather than by trusting its offset. Uncorrectable BEAMS of a resolved ping (unweighable bin, no finite angle or range, `|theta| >= 90` deg, and -- review round 2 -- more than half `angle_bin_width_deg` beyond the outermost written bin or short of the nadir-most one, where the clamped end value was never measured; a gap between written bins is interpolated between its measured neighbours; review round 3: a table with more than one bin per mode and no `# angle_bin_width_deg:` cannot run that test, so it loads with a warning the callers print) take the same policy; the correction runs inside the estimator with const parameters, so they are counted where the ping is stamped instead (PR 2 review round 1): `countBeam` applies the estimator's own test (`tableBeamStatus`) to every sounding with an intensity and counts the uncorrectable ones per (mode, reason) in the report, as submitted (before CUBE's own gates). The loader also reports each mode's unweighable bins at load time. The reserved `correction_idx` values are 0 unresolved, `0xFFFE` exclude, `0xFFFF` identity; entries 1..`0xFFFD`.
10. **Time-ordered association.** Everywhere a ping uses the latest SonarInfo whose `header.stamp` is at or before the ping stamp; the history is keyed by stamp and deduplicated (heartbeats repeat the change stamp). Derivation: SonarInfo and detections are read in one bag-time-ordered merge, and each ping is attributed after a 1 s bag-time guard (with `--box`, after the TF guard), so a SonarInfo recorded slightly after its first ping is still seen. import_bag (PR 2): `sonar_info` joins the main-pass topic filter and is resolved at drain time in the TF-frontier queue. Live node (PR 2): reader QoS depth 10 (writer stays transient_local depth 1); resolver and table survive the reset service's `buildSession`; a late SonarInfo is never applied retroactively, and the stale window is accepted and counted (`stale` / `late_sonar_info` in the resolver counts; a ping is stale only when the late message would have changed its correction; review round 2: a ping counts at most once however many late messages land before it, and one that restores the correction it got takes the count back). **The history is bounded (PR 2 review round 1, host direction):** a message whose state equals the one in force at its stamp is not stored (a bridge republishing on every ping under a steady mode adds nothing) -- **reverted in review round 2:** folding the same state under a new stamp broke out-of-order association (A@100 kept, A@300 folded, a late B@200 then handed a ping at 350 B), and the derive tool keeps distinct stamps, so only a same-stamp re-delivery is deduplicated now and the window and cap alone bound the history; on every `addSonarInfo` the entries stamped before `newest resolved ping - 60 s` are dropped except the newest one at or before that cut (pings drain in stamp order offline and arrive in order live, so nothing older can be selected again), and a hard cap of 4096 entries drops the oldest; without it a node under alternating multi-mode pinging grew by one entry per ping for its whole life. **Time going backwards (review round 2, host direction):** the anchor is a running maximum, so after a sim restart or a looped bag it stayed on the old timeline and pruned the new one to one entry per message; a ping more than the window behind the anchor now re-anchors on itself (and clears the stale look-back), a SonarInfo stamped behind the window is stored unpruned and never folded into an older entry, and when such SonarInfo arrived with nothing in the window since, the re-anchoring ping drops the old timeline's entries. **Review round 3 (host direction):** the re-anchoring ping also drops every entry more than the window ahead of it, so a new timeline whose first ping precedes its first SonarInfo is unresolved until that SonarInfo arrives, never given the old run's mode; behind-window states are exempt from the 4096 cap (which drops only the window's states, oldest first, never the one in force at the newest resolved ping) and have a 4096 cap of their own. **Review round 4 (host direction):** with no behind-window SonarInfo the re-anchoring ping drops EVERY entry, not only those more than the window ahead: the old run's state in force is stamped near its start (SonarInfo on change, heartbeats keep the stamp), which can sit within the window ahead of the new run's first ping and was handed to the new run for the rest of the run. A ping (or a SonarInfo and a ping) delivered more than the window late is indistinguishable from a restart by arrival order and is read as one -- accepted; the cost is unresolved pings until the next SonarInfo or heartbeat. No clock-jump callback: it fires only for the ROS time source, not for a wall-clock replay or import_bag. The node's unresolved warning treats a negative elapsed time (the clock went backwards) as "warn now". **The cap holds for waiting pings (review round 2):** import_bag reads SonarInfo ahead of the pings waiting for the TF frontier, so it tells the resolver the oldest waiting ping (`holdFrom`) and neither the window nor the cap drops the state in force there or any later one; the history then exceeds 4096 only by the states read ahead of pings import_bag is itself holding. **The live node reads `/soundings` clouds, which carried no frequency (2026-11-06):** `detections_to_pointcloud` now writes a `frequency` field (Hz, `ping_info.frequency`, the same value on every point; point_step 28 → 32) and the node reads it when present; an older cloud without it keys as `?kHz`, matches no entry, and gets the fallback.
11. **`batch_regen`** rejects tables with any entry other than `*` (no SonarInfo source). **Fingerprint** (ADR-0003): the `backscatter_correction` key, additive within schema 2, `fromJson` accepting files without it; curve hash defined for `auto` as a canonical serialisation of the adopted curve.

## Approach

Two PRs on this branch lineage (operator decision).

**PR 1 — science first (this branch's first PR): no estimator change.**
0. `--accumulation-cache`: pickle the accumulated builder after the bag pass; reuse it (identity-checked: bags, topics, box, bin width, exclusion, edges) to refit in seconds — Appledore's bag pass is 35 min per iteration of the fit settings.
1. `derive_angular_response.py --by-mode` on the cube#170 version: `--sonar-info-topic` (default: the detections topic's sibling `sonar_info`), time-ordered merge of detections + SonarInfo (+ TF with `--box`) through the existing `merged_messages`/`PingLocator`, `canonical_mode_key` (decision 1), per-mode accumulation in (signed angle bin, 0.01-decade range cell) sufficient statistics (n, sum, sum of squares; the node grid is placed relative to R0 after the pass), the joint fit (decisions 2-4), variance (6), switch events and chained offsets (5), table writer (7), optional `--diagnostics-out` JSON, run summary on stdout. Legacy output unchanged without `--by-mode`; `--by-mode --remove-tl` refused.
2. `test/data/mode_keys.json` key vectors; a table fixture `test/data/angular_response_table_v1.csv` written by the Python test (regenerated with `GOLDEN_REGENERATE=1`) and read by the C++ loader test, which must return an empty curve; the marine_tools mirror is imported read-only by the Python test and must return an empty curve. The C++ loader is not changed (letter-first keys already make it skip every row).
3. README: `--by-mode`, the table format, the key spec, the diagnostics, what remains for PR 2.
4. Appledore diagnostic (read-only on the NAS bags, outputs under `.agent/scratchpad/appledore_backscatter/`): per-mode pings, offsets vs the reference with SE, up/down agreement, misfit, pair counts at 2 s, binned residuals. These gate format v1.

**PR 2 — estimator, importer, node (built 2026-11-06).** Split into two units: `backscatter_table.{h,cpp}` (the key spec in C++ against the shared vectors, the strict `angular-response-table v1` loader keyed on `# format:`, the per-beam lookup `correctWithTable` with the angle-group range term and the fallback policy) and `backscatter_mode.{h,cpp}` (the message-free resolver: stamp-keyed SonarInfo history, key → entry with the declared-state check, counters and report; `sonar_info_curve.h` adds `sonarInfoStateFrom` so the core library stays free of `marine_interfaces`). `correctBeamIntensity(..., correction_idx)` with the legacy path byte-identical for index 0, `Parameters::backscatter_table` + `backscatter_mode_fallback`, `GeoMapSheet::setBackscatterTable`, `MultiLevelAccumulatorConfig`, `correction_idx` on `Sounding`/`DepthAndUncertainty`/`SpilledSounding` through `Node::update`/`queueEstimate`/`Hypothesis::recordBeam` (an excluded beam returns NaN and is skipped), import_bag main-pass SonarInfo (topic added to the read filter, resolved at drain time) + `--backscatter-mode-fallback` + `--backscatter-mode-min-pings` + the resolver report + a table that does not load is an error, live node (`backscatter_mode_fallback`, `backscatter_mode_min_pings`, QoS depth 10, `buildSession`, cleanup report, a broken table fails configure) + the cloud `frequency` field, batch_regen refusal, fingerprint `backscatter_correction` key (mode, kind, SHA-256 via OpenSSL, fallback, floor; `isStale` compares it; a pre-#172 file without the key is stale), ADR-0007 per-pulse-mode addendum and ADR-0003 amendment, README. Still to do on this PR: the marine_tools mirror follow-up issue, the Appledore re-import (candidate D) with the leave-one-bag-out check.

## Open Questions

- Does Appledore's misfit stay under 1.5 dB with quarter-decade nodes, or is a 2-D or finer table needed? (PR 1 measures it.) **Run 1 (2026-10-30): no** — pooled rms 0.6-0.7 dB, but 5-13 dB in the 10-30 deg group of every mode → range term per angle group (decision 2, 2026-11-02). **Run 2 (11-02, groups):** junk long-range beams anchored the 20 µs term (offset +49.5 dB) → end-node trimming + share floors. **Run 3 (11-02, trimmed):** offsets sane (20 µs −14.3, 50 µs −1.0, 10 ms FM −36.9, 5 ms FM −5.0 dB vs the 1 ms FM reference), misfit rms 0.5-0.6 dB for the three main modes, max 3.2-3.8 dB; what remains is step-like structure inside a quarter decade — the 50 µs mode at 3-4 m slant range (±2-3 dB over millions of beams), the 20 µs mode at 7-9 m — and eighth-decade nodes (`--range-node-spacing-decades 0.125`, refit from the cache) did not lower it (max 2.4-4.8 dB), so the default spacing stays 0.25 and the flag exists for sonars where it helps. The 50 µs ↔ 20 µs offset disagrees between switch directions by 1.4 ± 0.15 dB (seabed-with-depth bias, as predicted in decision 5). **Run 4 (11-02, final PR 1 code after two review rounds):** the three main modes are unchanged (20 µs −14.18, 50 µs −0.85 dB; misfit max and rms identical to run 3). The 5 ms FM mode (169 pings, chained through two switches) moved from −4.96 to +3.25 dB, far beyond its 1.3 dB standard error, when the intercepts stopped being span-masked: its offset is NOT trustworthy, and the SE understates that for a mode with so few switches — the rare-mode entries stay (operator decision) but PR 2's fallback policy, not this offset, should decide what happens to those 169 pings. Whether the remaining 2-3 dB sub-node residual is acceptable for the product is the operator's call; the misfit flag stays on until it is.
- Is 2 s the right window? PR 1 reports pair counts and up/down agreement at 2 s. **Carried to PR 2's Appledore re-import**: run 3 used 1806 switches at 2 s with SEs of 0.06-0.10 dB on the main pairs, and the one disagreement (50 µs ↔ 20 µs, 1.4 dB) is the seabed-with-depth bias decision 5 predicts, which a different window would not remove; the window is part of the cache identity, so a different value costs a new bag pass.
